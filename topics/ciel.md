# Ciel

One app that receives the failures of all the user's apps and shows and manages the health of
every device, app and the network: a personal sysadmin. Repo rom618/ciel at `~/Playground/ciel`
(renamed from nexus, which collides with Sonatype Nexus). The product spec is its `SPEC.md`; how
to build, run and deploy is its `README.md`. Live at https://ciel.wuling.dev (roberta, home-server
`stacks/ciel`): milestones 1 to 6 done on 2026-10-11 (foundation, failures, agent, health and
alerts, change journal and docs, containers and actions). Next: 7 (charts, Grafana retired).

## Facts

- Motivating incident: `restic-maintain` failed every week from 2026-09-19 with one desktop
  notification each and nobody noticed (`topics/backups.md`). Ciel must keep a failure open, red on
  the bar, and reminded until resolved.
- Stack: Rust (axum, sqlx, SQLite) and React + TypeScript + Vite + Tailwind, same as the media app.
  Hub in a Docker stack in the home-server repo (`stacks/ciel`, data `/srv/data/ciel`), an agent
  per device (root systemd service, outbound WebSocket, local spool), a per-user notifier on the
  laptop. Nothing may tie the hub to roberta (later a Raspberry Pi 5 with an SSD).
- Ingest is Sentry-compatible (existing SDKs work), plus plain JSON and systemd failures.
- Replaces Dockge (stacks: start, stop, restart, live logs) and Grafana. Prometheus stays the
  metrics store; the laptop reaches it by remote write.
- Management levels 1 and 2 only: view and links, restart or run now or logs. No compose editing,
  no deploys, no web shell.
- Devices: laptop and home server now; network gear and the Ciel box later; not the phone. Apps: own
  apps, self-hosted apps (Vaultwarden planned), online services, desktop apps.
- Alerts: desktop with a bar indicator (left click runs the default action) and phone through
  ntfy. Every agent alerts when the hub dies (no outside service).
- Users: `work` is a sub-account of `rom`. Every item has an owner (rom, work, shared); rom sees
  all, work sees work and shared only.
- Network is in scope (VPNs, tailnets, Wi-Fi profiles, DNS, firewall, Flybox, Pi-hole later); read
  first, every change guarded by automatic rollback. LAN only until Tailscale; hosted Tailscale
  first (Headscale needs a VPS because of CGNAT). Tailscale on Linux is machine-wide, so moving
  the vesscam tailnet to work means owner `work` plus `tailscale set --operator=work`.
- A stack's owner is its `dev.ciel.owner` label, else the Ciel app with the same name, else the
  device's owner. A personal project's containers on a shared device need a rom-owned app (done for
  `location-browser` on 2026-10-11), or they count as shared and reach overseer's inventory.
- Docs feed: the change journal and inventory generated by Ciel go to the docs repos
  (`topics/docs.md`), routed by owner; media paths are filtered out at the agent.
- Milestones (SPEC section 15): 1 foundation; 2 failures (Camille reports to it); 3 agent
  (systemd failures, heartbeats, backups covered); 4 health and alerts (restic incident cannot go
  unnoticed); 5 change journal and docs; 6 containers (Dockge retired); 7 charts (Grafana
  retired); 8 network read; 9 network act; 10 more sources (status pages, coredumps, Pi-hole,
  Vaultwarden, dedicated box).
